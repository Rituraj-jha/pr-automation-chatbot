# Skill: S3 Bucket

## Purpose

Use this skill when the user asks for an S3 bucket, bucket, storage, object storage, or data lake storage.

## Source of Truth

Do **not** rely on this markdown for exact field lists, allowed values, or required/optional status.
Those come dynamically from `get_resource_info`, which reads `config/resources/s3.yaml`.

Use the structured config returned by `get_resource_info` for:

- required fields
- allowed options
- defaults
- dependencies
- editability
- validation patterns
- normalization hints

## What to Ask

Ask only the missing required collected fields from the structured config.
For S3 today, those fields are expected to come from config as:

- `plat_env`
- `intake_id`
- `usage_type`
- `enterprise_or_func_name`
- `enterprise_or_func_subgrp_name`

When asking, show valid choices from the config, not from memory.
If a field has options, ask the user to pick one of those exact options.

## Multi-Resource Behavior

If S3 is requested with other resources:

1. Ask common missing fields first only.
2. Do not ask `usage_type` until the resource-specific step.
3. After common fields are stored, ask S3-specific missing fields in one concise message.

## Normalization Guidance

Use config normalization before rejecting values.
Examples of safe behavior:

- Accept obvious environment synonyms if config maps them, such as production → prd.
- Accept casing differences if config/options allow normalization.
- Do not create new option values from user wording.

If user wording does not map to a configured option, ask for one valid configured option.
For example, if the user says "analytics exports" and config does not contain `Export`, ask them to choose from the configured `usage_type` options.

## Response Style

Keep responses short.

Single S3 example:
"I can create the S3 bucket. Please provide the missing fields: intake ID, usage type, enterprise, and subgroup."

Multi-resource example:
"First, please provide the shared fields: environment, intake ID, enterprise, and subgroup."

## Error Recovery

- If tool validation rejects a value, show the valid choices returned from config and ask for the corrected field only.
- If `intake_id_check.valid` is false, ask for a valid approved intake ID and do not proceed to confirmation.
